# Copilot Code G2

A voice-friendly, multi-session coding assistant web app powered by the
**GitHub Copilot CLI** (`copilot`) — inspired by
[claude-code-g2](https://github.com/sam-siavoshian/claude-code-g2), which does
the same thing on top of the Claude CLI and Even Realities G2 AR glasses.

> The original project is built around proprietary AR-glasses hardware and the
> Even Realities SDK, which aren't available in this environment. This port
> keeps the same backend architecture — a session manager that spawns the AI
> CLI headlessly per turn, streams events over SSE, persists sessions to disk,
> and gates everything behind a bearer token — but swaps the Claude CLI for
> the GitHub Copilot CLI and replaces the glasses HUD with a lightweight
> browser chat UI that anyone can run and test.

```
┌───────────────────────────────┐
│  frontend/ (Vite + React)     │
│  chat UI in the browser       │
│  • App.tsx   session UI       │
│  • api.ts    authFetch + SSE  │
└───────────────┬────────────────┘
                │ HTTP + bearer token
                ▼
┌───────────────────────────────┐
│  backend/ (Node + Express)    │
│  • /projects   whitelisted dirs│
│  • /sessions   CRUD            │
│  • /sessions/:id/messages      │
│  • /events     SSE stream      │
│  • SessionManager              │
│        │ spawn                 │
│        ▼                       │
│  copilot -p "<message>" -s     │
│    --no-ask-user [--resume ID] │
└───────────────────────────────┘
```

The backend spawns the `copilot` CLI headlessly (`-p`) for each turn, streams
its stdout to the browser over Server-Sent Events, and persists the
conversation to `~/.copilot-g2/sessions.json`. When the CLI's own session id
can be recovered it's reused via `--resume`; otherwise the manager falls back
to replaying the transcript as context for the next turn.

## Requirements

* Node.js 20+
* The [GitHub Copilot CLI](https://github.com/github/copilot-cli) installed
  and authenticated (`copilot login`), or a `COPILOT_GITHUB_TOKEN` /
  `GH_TOKEN` environment variable set for headless auth.

## Setup

### Backend

```sh
cd backend
npm install
npm run dev
```

On first run this generates `~/.copilot-g2/config.json` with a random bearer
token (file mode `0600`) and an empty `projects` list. Add at least one
project before creating sessions:

```json
{
  "token": "<auto-generated>",
  "projects": [
    { "name": "myapp", "path": "/Users/you/code/myapp" }
  ],
  "defaultProjectName": "myapp",
  "model": "gpt-5.2",
  "allowAll": false
}
```

* `PORT` (env var, default `8787`) — port the backend listens on.
* `allowAll` maps to the CLI's `--allow-all` flag (grants every tool/path/url
  permission). Leave it `false` unless you trust the whitelisted projects.

### Frontend

```sh
cd frontend
npm install
npm run dev
```

Open the printed local URL, paste the bearer token from
`~/.copilot-g2/config.json` into the **Connect** field, then create a session
and start chatting. Set `VITE_BACKEND_URL` if the backend isn't on
`http://localhost:8787`.

## Project layout

```
backend/src/
  index.ts               Express app + routes
  config.ts               Config load/save + token generation
  auth.ts                 Bearer-token auth middleware (constant-time compare)
  events.ts                SSE pub-sub hub
  sessions/
    types.ts               Session/turn types
    store.ts                Disk-backed session store
    copilotProc.ts          Spawns the `copilot` CLI, parses its output
    manager.ts               Session orchestrator

frontend/src/
  App.tsx                  Chat UI: session list + transcript + composer
  api.ts                    authFetch helper + SSE client
```

## Testing

```sh
cd backend && npm test        # vitest: auth, config, store, CLI arg-building, manager
cd frontend && npm run build  # tsc + vite build
```

## Security notes

* The bearer token in `~/.copilot-g2/config.json` is the only auth layer —
  anyone with it can run Copilot CLI turns (including shell commands, if
  `allowAll` or broad `--allow-tool` permissions are granted) against your
  whitelisted projects. Treat it like a credential.
* Restrict the `projects` list to directories you trust.
* If the token leaks, delete `~/.copilot-g2/config.json` and restart the
  backend to generate a new one.
